# Scaling AI Development Across Teams

## Overview

Moving from individual AI usage to **team-wide AI adoption** requires:
- Shared conventions and standards
- Centralized skill libraries
- Approved tool catalogs (MCP servers)
- Governance and oversight
- Team onboarding and training

This demo shows how to scale responsibly without chaos.

## Shared Conventions

### Team CLAUDE.md Template

Every project has a `CLAUDE.md` at the root. It's the "north star" for all AI agents:

```markdown
# [Project Name]

## Commands
- `npm test` — Run tests
- `npm run dev` — Development server
- `npm run build` — Production build
- `npm run lint` — Lint and format

## Architecture
[Brief description of layers: routes → services → data access]

## Code Style
- TypeScript strict mode
- Async/await (no callbacks)
- Custom error types (extend AppError)
- JSDoc on all public functions

## Testing Requirements
- Jest with ts-jest
- Mirror src/ structure in tests/
- Minimum 80% line coverage
- Cover: happy path, edges, errors

## Boundaries
- No direct database access outside repository layer
- No console.log in production code (use logger)
- All external API calls via dedicated service
- Environment variables never committed

## Git Workflow
- Conventional commits: feat:, fix:, test:, docs:
- Feature branches off main
- PR required for all changes (including AI)
- Squash commits before merge (keeps history clean)
```

All agents read CLAUDE.md before working. It prevents inconsistency and rework.

### Standardized Skill Libraries

Team has a `skills/` directory with reusable prompts:

```
skills/
  api-endpoint.md          — Template for creating REST endpoints
  database-migration.md    — Template for writing DB migrations
  react-component.md       — Template for React components
  unit-test.md            — Template for writing tests
  refactor-service.md     — Template for refactoring services
```

When assigning work, team lead gives agent a skill:

```
"Create a new API endpoint for user invitations following the pattern in skills/api-endpoint.md"
```

This ensures consistency across all team members' AI agents.

## Governance

### Code Review Requirements

**All AI-generated code** goes through human review:

1. **Pre-PR**: AI agents must compile code, pass linting, pass tests
2. **PR Review**: Human reviews using `configs/review-checklist.md`
3. **Approval**: Senior engineer approves before merge
4. **Post-Merge**: Team lead spot-checks production behavior

### Cost Tracking

Budget AI usage per team:

```json
{
  "team_budgets": {
    "backend": "$50/month",
    "frontend": "$30/month",
    "devops": "$20/month"
  },
  "tracking": "Log Claude API calls with git commits",
  "review": "Monthly cost audit"
}
```

Teams stay within budget by:
- Using smaller models when appropriate
- Reusing prompts/skills instead of writing new ones
- Batching work (fewer sessions, more work per session)

### Audit Trail

Track which code was AI-generated:

```bash
git commit -m "feat: user authentication

Co-authored-by: Claude <ai@anthropic.com>
Generated via: multi-phase-planning
Cost: ~3000 tokens"
```

Later:
```bash
git log --grep="Co-authored-by: Claude" | wc -l
# Shows: 47 commits generated by AI
```

## Onboarding New Developers

### Getting Started with AI

New team members need a guide:

**1-hour onboarding**:
1. Read this project's CLAUDE.md (10 min)
2. Review 3 example skills in skills/ (15 min)
3. Watch 5-minute demo of using Claude Code with the project (5 min)
4. Do a small task with Claude guidance (20 min)
5. Review an AI-generated PR (10 min)

**What they learn**:
- Our patterns and conventions
- How to delegate to Claude effectively
- How to review AI-generated code
- When to use AI vs. doing it manually

### Required Skills for Your Domain

Backend team must be proficient with:
- `skills/api-endpoint.md` — Creating API endpoints
- `skills/database-migration.md` — Database changes
- `skills/unit-test.md` — Writing tests
- `skills/refactor-service.md` — Refactoring

Frontend team must be proficient with:
- `skills/react-component.md` — Building components
- `skills/unit-test.md` — Testing components
- `skills/refactor-service.md` — Refactoring

### Team Norms

Set expectations:

- ✅ **OK**: Use Claude Code for routine tasks, boilerplate, tests
- ✅ **OK**: Ask Claude for code reviews and suggestions
- ✅ **OK**: Use Claude to learn unfamiliar libraries
- ❌ **Not OK**: Blindly copy Claude output without review
- ❌ **Not OK**: Deploy AI code without human testing
- ❌ **Not OK**: Use AI for security-critical code without senior review

## Shared Subagent Library

Beyond skills, maintain a library of custom subagents in `.claude/agents/`:

```
.claude/agents/
  code-reviewer.md    — Reviews code for quality and your team's standards
  test-writer.md      — Writes tests following your testing conventions
  security-auditor.md — Checks code against your compliance requirements
  api-designer.md     — Designs API endpoints following team patterns
```

Each subagent has YAML frontmatter with tool restrictions and model selection, plus a focused system prompt encoding your team's expertise.

**Distributing via plugins**: Package subagents into a plugin so any project can install them with one command. When someone improves a subagent's prompt, every project gets the update on the next plugin refresh.

Check subagent configs into version control. When a team member discovers a better prompt for code review, the whole team benefits.

## Getting Started

1. Copy `templates/CLAUDE.md.template` to your project as `CLAUDE.md`
2. Customize for your project
3. Create `skills/` directory with your team's standard prompts
4. Create `.claude/agents/` with your team's shared subagents
5. Establish code review process using risk management checklist
6. Measure impact (velocity, defects, review time)
7. Refine skills, subagents, and CLAUDE.md based on team feedback

## Common Challenges & Solutions

### Challenge: Inconsistent Code Quality
**Solution**: Enforce CLAUDE.md and code review checklist

### Challenge: Cost Overruns
**Solution**: Set per-team budgets, require approval for large tasks

### Challenge: Team Members Blame AI for Poor Code
**Solution**: Emphasize "AI assists, humans decide"; code review catches issues

### Challenge: Skill Library Becomes Stale
**Solution**: Dedicate 1 hour/week to reviewing and updating skills

## Key Takeaway

Scaling AI across teams isn't about letting AI run wild—it's about creating structure, standards, and oversight that let teams move faster while maintaining quality. Clear CLAUDE.md, shared skills, code review, and cost tracking keep the chaos at bay.
